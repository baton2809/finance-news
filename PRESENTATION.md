# Презентация: RAG система для финансовой грамотности

**Команда**: A3R
**Дата**: Январь 2026
**Технологии**: Python 3.11, FAISS, Streamlit, DeepSeek API, Docker, RAGAS

---

## 1. Проблема

**Доменная проблема**: Низкий уровень финансовой грамотности населения приводит к неэффективным финансовым решениям.

**Техническая проблема**:
- Существующие FAQ системы статичны и не адаптируются под контекст
- Поисковые системы выдают слишком общую информацию
- LLM без RAG генерируют неточную информацию (галлюцинации)

**Решение**: Система RAG (Retrieval-Augmented Generation), которая:
- Ищет релевантные фрагменты из базы знаний
- Генерирует точные ответы на основе найденного контекста
- Оценивает качество через RAGAS метрики

---

## 2. Цели и задачи проекта

### Цели
1. Создать систему вопросов-ответов по финансовой грамотности
2. Обеспечить точность и отсутствие галлюцинаций
3. Оценить качество через метрики RAGAS

### Задачи
- Построить векторную базу данных на основе корпуса текстов
- Реализовать 3 режима RAG (document-level, chunk-based, chunk+reranking)
- Интегрировать RAGAS метрики для оценки качества
- Создать веб-интерфейс для пользователей
- Контейнеризировать систему через Docker

## 3. Сбор данных

### Источник данных
**Файл**: `train_data.csv` (5.8 MB)
- ~1200 документов по финансовой грамотности на русском языке
- Темы: кредиты, инвестиции, страхование, налоги, ПСК, инфляция

### Дополнительные данные
- `questions.csv` - набор тестовых вопросов
- `questions_with_references.csv` - 100 вопросов с референсными ответами для RAGAS

### Методы обработки
1. **Векторизация**: multilingual-e5-small (384 dim) - эмбеддинги текстов
2. **Chunking**: разбиение документов на фрагменты 1000 символов с overlap 200
3. **Индексация**: FAISS IndexFlatIP (~12847 векторов)

## 5. Компоненты системы

### Основные компоненты

| Компонент | Технология | Роль |
|-----------|------------|------|
| **Embeddings** | multilingual-e5-small | Векторизация текстов |
| **Vector DB** | FAISS IndexFlatIP | Хранение и поиск векторов |
| **LLM** | DeepSeek API | Генерация ответов |
| **Evaluation** | RAGAS 0.4.2+ | Оценка качества RAG |
| **Web UI** | Streamlit | Пользовательский интерфейс |
| **Reverse Proxy** | Nginx | Rate limiting, WebSocket support |
| **Orchestration** | Docker Compose | Управление контейнерами |

### Режимы RAG

**v1: Document-Level**
- Векторизация целых документов
- Скорость: 2-3 сек
- Context Precision: ~0.65

**v2: Chunk-Based** (рекомендуется)
- Разбиение на фрагменты (1000 символов, overlap 200)
- Скорость: 3-4 сек
- Context Precision: ~0.75

**v3: Chunk + LLM Reranking**
- v2 + переранжирование топ-20 через LLM
- Скорость: 5-7 сек
- Context Precision: ~0.85

## 6. Оценка качества

### RAGAS метрики

| Метрика | Описание | Требует референс | Диапазон | Цель |
|---------|----------|-----------------|----------|------|
| **Faithfulness** | Нет галлюцинаций | Нет | 0.0-1.0 | >0.85 |
| **Answer Relevancy** | Релевантность ответа | Нет | 0.0-1.0 | >0.80 |
| **Context Precision** | Точность извлечения | Да | 0.0-1.0 | >0.75 |
| **Context Recall** | Полнота извлечения | Да | 0.0-1.0 | >0.80 |

### LLM-as-Judge (дополнительно)

- **LLM Relevance**: субъективная оценка 1-5
- **LLM Faithfulness**: субъективная оценка 1-5

### Фреймворки

- **RAGAS** - RAG Assessment специально для RAG систем
- **LangChain** - интеграция LLM и embeddings
- **Sentence Transformers** - векторные эмбеддинги

## 7. Эксперименты

### Что пробовали

#### 7.1 Выбор модели эмбеддингов

| Модель | Размерность | Качество RU | RAM |
|--------|-------------|-------------|-----|
| paraphrase-multilingual-MiniLM | 384 | Среднее | 500MB |
| multilingual-e5-large | 1024 | Отличное | 2GB |
| **multilingual-e5-small** | 384 | Хорошее | 500MB |

**Выбрано**: multilingual-e5-small

#### 7.2 Размер чанков

| Chunk Size | Overlap | Качество |
|------------|---------|----------|
| 500 | 100 | Среднее |
| **1000** | **200** | Хорошее |
| 2000 | 400 | Низкое |

**Выбрано**: 1000 символов, overlap 200

#### 7.3 Reranking (V2 vs V3)

| Метрика | V2 | V3 | Улучшение |
|---------|----|----|-----------|
| Context Precision | ~0.75 | ~0.85 | +13% |
| Время ответа | 3-4s | 5-7s | +75% |
| API calls | 2 | 3 | +50% |

### Что работало ✓

1. **Chunking** - критически улучшает точность поиска
2. **LLM Reranking** - исправляет ошибки векторного поиска
3. **RAGAS метрики** - объективнее LLM-as-Judge
4. **E5-small embeddings** - баланс качество/скорость
5. **Streamlit UI** - быстрая разработка интерфейса
6. **Docker Compose** - простая оркестрация Nginx + Web

### Что НЕ работало ✗

1. **Doc-level embeddings (V1)** - теряют детали
2. **Слишком маленькие чанки (<500)** - фрагментированный контекст
3. **RAGAS с DeepSeek по умолчанию** - требуется strictness=1
4. **Высокий top_k без reranking** - много шума
5. **E5-large в Docker** - медленная загрузка

### Технические проблемы и решения

**Проблема 1**: RAGAS 0.4.2+ возвращает списки вместо скаляров
- **Решение**: Функция `extract_metric()` для обработки обоих форматов

**Проблема 2**: DeepSeek API не поддерживает `n>1`
- **Решение**: `AnswerRelevancy(strictness=1)` вместо `strictness=3`

**Проблема 3**: Answer Relevancy требует `strictness=3` по умолчанию
- **Решение**: Явная настройка `AnswerRelevancy(strictness=1)`

### Итоговые метрики (V2 - рекомендуемый режим)

- **Context Precision**: ~0.75 (цель >0.75) ✓
- **Faithfulness**: >0.85 (цель >0.85) ✓
- **Answer Relevancy**: >0.80 (цель >0.80) ✓
- **Время ответа**: 3-4 сек
- **API calls**: 2 на запрос

## 8. Итоговый продукт

### Возможности системы

1. **Веб-интерфейс (Streamlit)**
   - Ввод вопросов на русском языке
   - 4 примера вопросов с референсными ответами
   - Выбор режима RAG (v1/v2/v3)
   - Настройка параметров (Top-K, Final-K)
   - Отображение метрик качества
   - Просмотр источников (контекст)
   - История последних 10 запросов

2. **CLI режим**
   - Batch обработка вопросов
   - Генерация CSV с результатами
   - Детальные метрики в `metrics_detailed.csv`

3. **Оценка качества**
   - RAGAS метрики в реальном времени
   - LLM-as-Judge дополнительные оценки
   - Визуализация метрик в карточках

### Интерфейс взаимодействия

**Веб-интерфейс**:
```bash
docker-compose up --build

```

**CLI**:

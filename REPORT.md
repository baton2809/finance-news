# Отчёт: RAG система для финансовой грамотности

**Проект**: Retrieval-Augmented Generation система для ответов на вопросы по финансовой грамотности
**Дата**: Январь 2026
**Стек**: Python 3.11, FAISS, Streamlit, DeepSeek API, Docker, RAGAS

---

## 1. Функционал интерфейса

### 1.1 Веб-интерфейс (Streamlit)

| Функция | Описание |
|---------|----------|
| Ввод вопросов | Текстовое поле для вопросов на русском языке |
| Примеры с референсами | 4 готовых вопроса для полной RAGAS оценки |
| Выбор режима RAG | v1/v2/v3 с описанием |
| Настройки поиска | Top-K (3-30), Final-K (1-5) |
| Метрики качества | RAGAS метрики и LLM-as-Judge |
| Просмотр контекста | Разворачиваемая секция с фрагментами |
| История запросов | Последние 10 запросов с метриками |

**Обработка ошибок**: Проверка API ключа, валидация ввода, информативные сообщения на русском.

**UX**: Минималистичный дизайн, цветовое кодирование, карточки метрик, адаптивный layout.

### 1.2 CLI интерфейс

```bash
docker-compose --profile cli run cli python main.py --mode v3
docker-compose --profile cli run cli python main.py --mode v2 --limit 10
```

## 4. Метрики качества системы

### 4.1 RAGAS метрики

| Метрика | Описание | Требует референс | Диапазон | Цель |
|---------|----------|-----------------|----------|------|
| Faithfulness | Нет галлюцинаций | Нет | 0.0-1.0 | >0.85 |
| Answer Relevancy | Релевантность ответа | Нет | 0.0-1.0 | >0.80 |
| Context Precision | Точность извлечения | Да | 0.0-1.0 | >0.75 |
| Context Recall | Полнота извлечения | Да | 0.0-1.0 | >0.80 |
| LLM Relevance | Субъективная оценка | Нет | 1-5 | >4.0 |
| LLM Faithfulness | Субъективная оценка | Нет | 1-5 | >4.0 |

### 4.2 Режимы RAG

#### v1: Document-Level
- Векторизация целых документов
- Быстрый поиск, низкое потребление памяти
- Context Precision: ~0.65

#### v2: Chunk-Based (Рекомендуется)
- Разбиение на фрагменты (1000 символов, overlap 200)
- Баланс скорость/качество
- Context Precision: ~0.75

#### v3: Chunk + LLM Reranking
- v2 + переранжирование топ-20 через LLM
- Лучшее качество, медленнее и дороже
- Context Precision: ~0.85

### 4.3 Сравнение версий

| Метрика | v1 | v2 | v3 | Улучшение v1→v3 |
|---------|----|----|-----|-----------------|
| Скорость (сек) | 2-3 | 3-4 | 5-7 | -133% |
| Context Precision | ~0.65 | ~0.75 | ~0.85 | +31% |
| API calls | 2 | 2 | 3 | +50% |

### 4.4 Модель эмбеддингов

**Выбрана**: `multilingual-e5-small` (384 dim)
- Хорошее качество для русского языка
- Быстрая работа
- Низкое потребление памяти (~0.5GB)

## 5. Проведённые эксперименты

### 5.1 Выбор модели эмбеддингов

| Модель | Размерность | Качество RU | Время индексации | RAM |
|--------|-------------|-------------|------------------|-----|
| paraphrase-multilingual-MiniLM | 384 | Среднее | 1 мин | 500MB |
| multilingual-e5-large | 1024 | Отличное | 5 мин | 2GB |
| **multilingual-e5-small** | 384 | Хорошее | 1.5 мин | 500MB |

**Результат**: `multilingual-e5-small` выбрана — хороший баланс качество/скорость.

### 5.2 Размер чанков

| Chunk Size | Overlap | Качество | Проблемы |
|------------|---------|----------|----------|
| 500 | 100 | Среднее | Фрагментированный контекст |
| **1000** | **200** | Хорошее | Оптимальный баланс |
| 2000 | 400 | Низкое | Размытые эмбеддинги |

**Результат**: 1000 символов с overlap 200.

### 5.3 Влияние reranking (V2 vs V3)

| Метрика | V2 | V3 | Улучшение |
|---------|----|----|-----------|
| Context Precision | ~0.75 | ~0.85 | +13% |
| Время ответа | 3-4s | 5-7s | +75% |
| API calls | 2 | 3 | +50% |

**Результат**: Reranking улучшает Context Precision на 13% ценой времени и стоимости.

### 5.4 Интеграция RAGAS метрик

**Проблемы**:
1. DeepSeek API не поддерживает `n>1`
2. RAGAS возвращает списки вместо скаляров (версия 0.4.2+)
3. Answer Relevancy требует `strictness=3` по умолчанию

**Решения**:
1. Настройка `AnswerRelevancy(strictness=1)`
2. Функция `extract_metric()` для обработки списков
3. Удаление явной установки `n` в ChatOpenAI

**Результат**: RAGAS интегрирован, Faithfulness и Answer Relevancy работают без референсов, Context Precision/Recall требуют референсов.

### 5.5 Что работало

1. Chunking — критически улучшает точность поиска
2. LLM Reranking — исправляет ошибки векторного поиска
3. RAGAS метрики — объективнее LLM-as-Judge
4. E5-small embeddings — баланс качество/скорость
5. Streamlit UI — быстрая разработка интерфейса
6. Docker Compose — простая оркестрация Nginx + Web

### 5.6 Что не работало

1. Doc-level embeddings (V1) — теряют детали
2. Слишком маленькие чанки (<500) — фрагментированный контекст
3. RAGAS с DeepSeek по умолчанию — требуется strictness=1
4. Высокий top_k без reranking — много шума
5. E5-large в Docker — медленная загрузка
